Create a CorrelationIdFilter (extends OncePerRequestFilter, @Order(Ordered.HIGHEST_PRECEDENCE)):
- Check for incoming X-Correlation-ID header
- If absent, generate a new UUID
- Store it in MDC as "correlationId"
- Add it to the response header X-Correlation-ID
- Clear MDC after the request completes

Create a RequestLoggingFilter (extends OncePerRequestFilter):
- Log at INFO: HTTP method, URI, query params, response status, and elapsed time in ms
- Format: "[{correlationId}] {method} {uri} → {status} ({elapsed}ms)"
- Do NOT log request/response bodies (for security)

Register both filters in a FilterConfig class.

Create a RateLimitingFilter (extends OncePerRequestFilter, @Component):
- Apply only to POST /api/v1/auth/token (skip all other paths)
- Maintain a ConcurrentHashMap<String, Bucket> keyed by client IP
- Resolve client IP: take the first value from X-Forwarded-For header, fallback to request.getRemoteAddr()
- Create buckets lazily via computeIfAbsent; each bucket uses Bandwidth.classic with Refill.intervally (all tokens refill at once per period — prevents gradual drip-through attacks)
- Configuration via RateLimitProperties (@Component @ConfigurationProperties(prefix = "rate-limit.auth")):
  - capacity (default 10): max burst
  - refillTokens (default 10): tokens added per period
  - refillPeriodMinutes (default 1)
- On exhaustion: return HTTP 429 with Retry-After header (seconds) and JSON body: {"status":429,"error":"Too Many Requests","message":"Rate limit exceeded. Retry after N seconds.","timestamp":"..."}
- Register in SecurityConfig before JwtAuthenticationFilter via .addFilterBefore(rateLimitingFilter, UsernamePasswordAuthenticationFilter.class)
- application.yml entry:
  rate-limit:
    auth:
      capacity: 10
      refill-tokens: 10
      refill-period-minutes: 1
