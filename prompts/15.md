Configure production observability:

1. Spring Boot Actuator:
    - Expose endpoints: health, info, metrics, prometheus
    - Add a custom health indicator OrderServiceHealthIndicator that checks DB connectivity
    - Configure /info to show app version, java version, and build timestamp from pom.xml (using maven resource filtering or build-info goal)

2. Custom Micrometer Metrics:
    - Create an OrderMetrics @Component that registers:
        - Counter: orders.created.total — NO customer_id tag (high-cardinality UUID tag causes unbounded time-series growth and registry memory leak); pre-register in constructor
        - Counter: orders.status.changed.total (tagged by from_status, to_status — bounded by enum); use registry.counter(name, tags) directly (Micrometer caches by meter ID), do NOT call Counter.builder().register() on every invocation
        - Timer: orders.creation.duration (measure createOrder method execution time)
        - Gauge: orders.active.count (query the repo for non-terminal statuses)
    - Inject and use this in OrderService at the appropriate points

3. Structured Logging:
    - Create a logback-spring.xml that:
        - In dev profile: use standard console pattern with colors
        - In staging/prod profile: use LogstashEncoder for JSON structured logging
        - Include fields: timestamp, level, logger, message, correlationId (from MDC), thread
