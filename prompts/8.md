Create the OrderService class:

Inject SecurityUtils (see security package) via constructor into OrderServiceImpl.

- createOrder(CreateOrderRequest):
   - If not admin, assert request.customerId() equals SecurityUtils.getCurrentUserId(); throw AccessDeniedException otherwise
   - Look up the customer by ID, throw EntityNotFoundException if not found
   - Map the request to an Order entity
   - Generate a unique order number (ORD- + 8 alphanumeric characters)
   - Set initial status to CREATED
   - Calculate each item's subtotal and the order's totalAmount
   - Save the order in a @Transactional method
   - Publish an OrderCreatedEvent via Spring's ApplicationEventPublisher after save
   - Return the saved order mapped to OrderResponse

- getOrderByOrderNumber(String orderNumber):
   - Fetch with items eagerly loaded (use @EntityGraph or JOIN FETCH query)
   - Throw EntityNotFoundException if not found
   - Assert caller is admin or owns the order (order.customer.id == getCurrentUserId()); throw AccessDeniedException otherwise

- listOrders(UUID customerId, OrderStatus status, Pageable pageable):
   - If not admin, override customerId to SecurityUtils.getCurrentUserId() regardless of what was passed
   - Use Spring Specification pattern to build dynamic filters
   - Two-query approach to avoid N+1:
     1. Call orderRepository.findAll(spec, pageable) to get page metadata + lightweight Order stubs (IDs only needed)
     2. Extract IDs: page.getContent().stream().map(Order::getId).toList()
     3. Call orderRepository.findAllWithItemsAndCustomerByIdIn(ids) — JOIN FETCH both orderItems and customer in one query
     4. Build a Map<UUID, Order> by ID for O(1) lookup, then re-map in original ID order to preserve sort
     5. Map to OrderResponse list and wrap in PagedResponse
   - Return a PagedResponse<OrderResponse>

- updateOrderStatus(String orderNumber, OrderStatus newStatus):
   - Annotate with @PreAuthorize("hasRole('ADMIN')") — admin only
   - Fetch the order, call order.transitionTo(newStatus) to validate the transition
   - Save and publish an OrderStatusChangedEvent
   - Return updated OrderResponse

- cancelOrder(String orderNumber):
   - Fetch the order; assert caller is admin or owns the order; throw AccessDeniedException otherwise
   - Call updateOrderStatus via this (bypasses @PreAuthorize — intentional, cancelOrder has its own ownership check)

Also create a CustomerService (interface + implementation):
Inject SecurityUtils via constructor into CustomerServiceImpl.
- createCustomer(CreateCustomerRequest):
   - Reject duplicate emails with IllegalStateException("Registration failed") — do NOT include the email in the message to prevent email enumeration
   - Use CustomerMapper to build the entity, then set passwordHash via passwordEncoder.encode(request.password())
   - Save and return CustomerResponse
   - Log at INFO using only the customer ID (never log the email or password)
- getCustomerById(UUID id):
   - If not admin, assert id equals SecurityUtils.getCurrentUserId(); throw AccessDeniedException otherwise
   - Return CustomerResponse or throw EntityNotFoundException
- getCustomerByEmail(String email):
   - Annotate with @PreAuthorize("hasRole('ADMIN')") — admin only
   - Return CustomerResponse or throw EntityNotFoundException
- verifyCredentials(String email, String rawPassword):
   - Load Customer entity by email; throw BadCredentialsException("Invalid credentials") if not found
   - Call passwordEncoder.matches(rawPassword, customer.getPasswordHash()); throw BadCredentialsException("Invalid credentials") if no match
   - Return CustomerResponse on success
   - Use the same error message for both failure cases to prevent email enumeration
- Inject PasswordEncoder (BCryptPasswordEncoder) and SecurityUtils via constructor
